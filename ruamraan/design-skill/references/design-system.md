# ระบบออกแบบรวมร้าน

ไฟล์นี้มี 3 ส่วน
1. **หลักการที่เรียนรู้จากคู่แข่ง** ใช้เป็นแนวคิด ไม่ใช่หน้าตา
2. **ระบบออกแบบรวมร้าน** ค่าที่ต้องใช้จริง
3. **เส้นแบ่ง** สิ่งที่ห้ามทำให้เหมือนคู่แข่ง

---

## ส่วนที่ 1 · หลักการที่เรียนรู้จากคู่แข่ง

ได้จากการทดลองใช้ระบบหลังร้านของคู่แข่งเมื่อ พ.ย. 2026 สิ่งที่ควรเก็บคือ "เหตุผล" ไม่ใช่ "หน้าตา"

| สิ่งที่เขาทำแล้วได้ผล | หลักการที่เราเอาไปใช้ |
|---|---|
| หน้าออเดอร์จัดตามสถานะพร้อมตัวเลขค้าง | งานหลังร้านคือการไล่เคลียร์คิว ให้สถานะเป็นตัวนำทาง และการกระทำถัดไปเปลี่ยนตามสถานะ |
| ข้อมูลหนาแน่น เห็นหลายออเดอร์ในจอเดียว | แอดมินทำงานปริมาณมาก อย่าเปลืองพื้นที่ แต่ต้องอ่านง่าย |
| แต่ละออเดอร์แสดงสินค้า ยอด ป้าย ขนส่ง ที่อยู่ ครบในแถว | ตัดสินใจได้โดยไม่ต้องเปิดรายละเอียด |
| เมนูจัดกลุ่มตามงาน (ขาย / ข้อมูล / รายงาน / ตั้งค่า) | เรียงเมนูตามลำดับงานในวัน |
| กติกา CF ตั้งค่าได้ (คำสั่งเพิ่ม คำที่ข้าม ยกเลิกอัตโนมัติ) | ให้ร้านปรับพฤติกรรมการจับออเดอร์ได้เอง |
| ข้อความอัตโนมัติมีตัวแปร | ลดการพิมพ์ซ้ำ และให้เห็นตัวอย่างก่อนใช้ |
| ประวัติการเปลี่ยนแปลงทุกออเดอร์ | ตรวจย้อนได้ว่าใครทำอะไร |

**จุดอ่อนของเขาที่เราต้องทำให้ดีกว่า:**
- **โครงแอป:** โหลดหน้าแบบแยกส่วน ช้า และมีหน้าขาว
- **หน้าตา:** แต่ละหน้าไม่เสมอกัน
- **ตัวกรอง:** กองไว้มากเกินบนหน้าแรก
- **ภาษา:** คำแปลแข็ง
- **โหมดมืดและการค้นหา:** ไม่มีโหมดมืด ไม่มีค้นหารวม
- **มือถือ:** ใช้บนมือถือไม่ได้

## ส่วนที่ 2 · ระบบออกแบบรวมร้าน (ค่าที่ต้องใช้)

### อัตลักษณ์

| โทเคน | สว่าง | มืด | ใช้ที่ |
|---|---|---|---|
| brand | `#0E9F87` | `#2CC4A7` | ปุ่มหลัก แท็บที่เลือก ลิงก์ |
| brand-soft | `#E2F5F1` | brand 14% | พื้นรายการที่เลือก ชิปที่ตั้งค่าแล้ว |
| live | `#FF5A5F` | `#FF7477` | ป้าย LIVE ตัวเลขแจ้งเตือน |
| bg | `#F4F6F7` | `#0C1215` | พื้นหลังแอป |
| surface | `#FFFFFF` | `#141C20` | การ์ด แผง |
| line | `#E2E7EB` | `#243036` | เส้นขอบ |
| text | `#16212A` | `#E5ECEF` | ข้อความหลัก |
| text-2 / text-3 | `#475562` / `#83919D` | `#AFBDC5` / `#76868F` | ข้อความรอง / คำอธิบาย |
| rail | `#0F171B` | `#090E10` | แถบเมนูซ้าย (เข้มทั้งสองธีม) |

**สถานะออเดอร์:**

| สถานะ | สว่าง | มืด |
|---|---|---|
| รอชำระ | `#D97706` | `#F5A524` |
| รอจัดส่ง | `#2563EB` | `#5B8CFF` |
| รอพิมพ์ใบปะหน้า | `#7C3AED` | `#A78BFA` |
| รอขนส่งเข้ารับ | `#0891B2` | `#22D3EE` |
| ส่งแล้ว | `#16A34A` | `#4ADE80` |
| ยกเลิก | `#83919D` | `#76868F` |

- **ฟอนต์:** Inter (ตัวเลขและอังกฤษ) + Noto Sans Thai จาก Google Fonts เนื้อหา 14px หัวหน้า 24px หนา 700 ตัวเลขใช้ `tabular-nums` รหัส (SKU, เลขพัสดุ) ใช้ฟอนต์ monospace
- **รูปทรง:** การ์ด 14px · ปุ่ม/ช่องกรอก 10px · ลิ้นชัก 18px · ป้ายสถานะ 8px · เงาบางมาก ใช้เส้นขอบเป็นหลัก
- **โลโก้:** สี่เหลี่ยมมุมมน gradient เขียวหัวเป็ด + จุดแดง live มุมขวาบน

### โครงแอป
- **แถบเมนูซ้าย** 236px สีเข้ม ย่อเหลือ 72px ได้
  - บนสุด: โลโก้ และตัวเลือกร้าน
  - เมนูเรียงเป็นกลุ่มคั่นเส้น: (หน้าหลัก · ไลฟ์ขาย · ออเดอร์ · กล่องข้อความ) / (สินค้า · ลูกค้า · ดรอปชิป) / (รายงาน · ตั้งค่า · หน้าลิงก์ชำระเงิน)
  - รายการที่เลือก: พื้นไล่สีเขียวจาง + เส้นเขียวซ้าย
  - ป้ายแจ้งเตือนสีแดง live และป้าย "LIVE" ที่เมนูไลฟ์
- **แถบบน** 60px: ช่องค้นหากว้าง (Ctrl/⌘K) · ปุ่ม "ออเดอร์ใหม่" · สลับธีม · การแจ้งเตือน · โปรไฟล์พร้อมบทบาท
- **หัวหน้า** ทุกหน้า: ชื่อ 24px + คำอธิบายหนึ่งบรรทัด + ปุ่มการกระทำชิดขวา

### หน้ารายการ (การ์ดเดียว)
1. **แท็บสถานะ** แบบเส้นใต้ ตัวเลขในวงรี (แท็บที่เลือก วงรีสีเขียวทึบ) แท็บแรกคือสถานะที่ต้องทำก่อน
2. **แถบตัวกรอง**
   - ช่องค้นหายาว ตามด้วยชิปขอบประ (ช่องทาง · วันที่ · ที่มา · ตัวกรองอื่น) กดแล้วเปิด popover
   - เมื่อตั้งค่าแล้ว ชิปเป็นขอบทึบพื้นเขียวจาง และมีปุ่ม × ล้าง
   - ขวาสุด: "มุมมองที่บันทึก"
3. **ตาราง** หัว 12px หนา 600 สีรอง · แถวมีเส้นคั่นบาง · คลิกแถวเปิดแผงรายละเอียด
   - คอลัมน์สุดท้ายเป็นปุ่มการกระทำถัดไป (ปุ่มโปร่งสีเขียว) + เมนู "…"
4. **แบ่งหน้า** ซ้าย "แสดง X จาก Y" ขวาเลขหน้า

เลือกหลายแถวแล้วมี **แถบลอยสีเข้ม** กลางล่างจอ

### ตารางออเดอร์
คอลัมน์:
- ออเดอร์ (ไอคอนช่องทาง + เลข + เวลา · ที่มา)
- ลูกค้า (ชื่อ + เบอร์)
- สินค้า (รูปซ้อนกันสูงสุด 3 + ชื่อแรก + จำนวน)
- ยอดรวม
- การชำระ (ป้าย)
- สถานะ (ป้ายมีจุด)
- ขนส่ง (ชื่อ + เลขพัสดุ)
- การกระทำ

### แผงรายละเอียดออเดอร์ (ลิ้นชักขวา)
- **หัว:** ป้ายสถานะ ป้ายการชำระ ร้าน ที่มา เวลา
- **แถบขั้นตอน** 5 ขั้น (รอชำระ → ส่งแล้ว) ขั้นที่ผ่านเป็นวงเขียวมีเครื่องหมายถูก
- **สองคอลัมน์**
  - ซ้าย: สินค้า (เพิ่มด้วยรหัส CF/SKU + Enter) + สรุปยอด · ความเคลื่อนไหว (timeline)
  - ขวา: ลูกค้าและที่อยู่ (ปุ่ม "แยกชื่อ เบอร์ และรหัสไปรษณีย์ให้") · การชำระเงิน · การจัดส่ง
- **ท้าย:** ยกเลิก (แดงโปร่ง) ชิดซ้าย · บันทึก + การกระทำถัดไป (ทึบ) ชิดขวา

### หน้าอื่น
- **หน้าหลัก:** KPI 4 ใบพร้อมกราฟเส้นเล็ก · กราฟพื้นที่ยอดขาย 7 วัน · "คิวงานวันนี้" (ไอคอนสีตามสถานะ) · ช่องทางขาย
- **ไลฟ์ขาย:** จอภาพสด + ตัวเลข 3 ช่อง · คอมเมนต์เป็นการ์ดมีอวาตาร์ (เขียว = สร้างออเดอร์ แดง = ของไม่พอ) · แผงขวาแท็บ "สินค้าบนไลฟ์ / ออเดอร์รอบนี้" สินค้าเป็นการ์ดปักหมุดได้
- **กล่องข้อความ:** 3 คอลัมน์ ฟองข้อความโค้ง ข้อความร้านพื้นเขียว การ์ดสลิปมีแถบส้มซ้าย ข้อความด่วนเป็นชิป
- **ตั้งค่า:** ศูนย์รวมหน้าเดียว เมนูย่อยซ้ายในการ์ด เนื้อหาเป็นการ์ดแถว (หัวข้อ + คำอธิบาย ซ้าย / ตัวควบคุม ขวา)
- **ลิงก์ชำระเงิน:** หัว gradient เขียว การ์ดลอยทับ ตัวเลือกจ่ายเป็นการ์ดมีไอคอน ปุ่ม "จ่าย ฿xxx" เต็มความกว้าง

## ส่วนที่ 3 · เส้นแบ่ง: สิ่งที่ห้ามทำให้เหมือนคู่แข่ง

ฟีเจอร์และแนวคิดทั่วไปใช้ได้ (แท็บสถานะ ตัวกรอง รหัส CF ข้อความอัตโนมัติ ลิงก์ชำระเงิน การเชื่อม marketplace) แต่ห้ามสิ่งต่อไปนี้

- [ ] **สีและฟอนต์:** ไม่ใช้ฟ้า `#0094FF` เป็นสีหลัก และไม่ใช้ชุดฟอนต์ Helvetica/Arial ล้วนแบบเขา
- [ ] **เมนูซ้าย:** ไม่ทำแบบพื้นเทาอ่อนที่เมนูที่เลือกเป็นแถบฟ้าทึบเต็มความกว้าง
- [ ] **ตัวกรอง:** ไม่ทำแบบแถวป้ายสีเทาชิดขวา กองหลายแถวบนหน้าแรก
- [ ] **แถวออเดอร์:** ไม่ใช้โครงแถบหัวเรียง "สถานะ · เวลา · เลข · ผู้ซื้อ · ร้าน · ผู้ดูแล" แล้วตามด้วยลิงก์คั่น " - "
- [ ] **ตารางรายละเอียด:** ไม่ใช้ตารางข้อมูลพื้นฐาน 3 คอลัมน์ที่แถวป้ายสีเทาสลับแถวค่า
- [ ] **ฟอร์มสินค้า:** ไม่ทำแบบซ้ายฟอร์ม ขวาแผงเทาที่มีสถานะ หมวด และแบรนด์
- [ ] **หน้าตั้งค่า:** ไม่ทำแบบพื้นเทา + แผงขาวกว้างคงที่
- [ ] **หน้าหลัก:** ไม่ใช้การ์ดทางลัด 8 ใบใหญ่ 4×2 พร้อมลูกศร
- [ ] **ข้อความ:** ไม่แปลชื่อเมนู ปุ่ม คำอธิบาย หรือเทมเพลตข้อความของเขามาใช้ เขียนใหม่ด้วยคำของเรา
- [ ] **ภาพและไฟล์:** ไม่ใช้โลโก้ ภาพประกอบ ไอคอนฟอนต์ หรือไฟล์ใด ๆ ของเขา
- [ ] **ชื่อ:** ไม่ใช้ชื่อหรือคำที่ทำให้คนเข้าใจว่าเป็นสินค้าเดียวกัน

ถ้าไม่แน่ใจว่าเหมือนเกินไปหรือไม่ ให้ถามว่า "ถ้าเอาโลโก้ออก คนที่เคยใช้ระบบเขาจะจำได้ไหมว่าเป็นของเขา" ถ้าจำได้ ให้เปลี่ยน
ข้อแนะนำนี้เป็นแนวปฏิบัติด้านการออกแบบ ไม่ใช่คำแนะนำทางกฎหมาย ก่อนเปิดตัวจริงควรให้ทนายตรวจ
