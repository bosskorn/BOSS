# รวมร้าน MVP: ไลฟ์ Facebook → ออเดอร์ → จัดส่ง

## เป้าหมายของ MVP

ทำฟังก์ชันเดียวให้ครบวงจรก่อน:

1. ร้านเชื่อมเพจ Facebook
2. ระบบดึงคอมเมนต์จากไลฟ์และโพสต์ (สดและย้อนหลัง)
3. คอมเมนต์ที่มีรหัสสินค้ากลายเป็นออเดอร์ ส่งลิงก์ชำระเงินทาง Messenger
4. ออเดอร์ทั้งหมดอยู่ในระบบจัดการออเดอร์ (OMS) ที่เดียว
5. ร้านส่งของด้วยขนส่งไหนก็ได้: เชื่อมบัญชีขนส่งของร้านเอง หรือใช้ขนส่งพาร์ทเนอร์ผ่านรวมร้าน **ไม่บังคับใช้ขนส่งของเรา**

**ยังไม่ทำใน MVP:**
- Shopee, Lazada, TikTok Shop, LINE
- ดรอปชิป
- ใบกำกับภาษีอัตโนมัติ
- แอปมือถือ

## ส่วนที่ 1 · เชื่อมต่อ Facebook

### สิทธิ์ที่ต้องขอ (Meta App Review)

| สิทธิ์ | ใช้ทำอะไร |
|---|---|
| `pages_show_list` | แสดงรายการเพจให้ร้านเลือก |
| `pages_read_engagement` | อ่านโพสต์ ไลฟ์ และคอมเมนต์ |
| `pages_read_user_content` | อ่านคอมเมนต์จากผู้ใช้ |
| `pages_manage_metadata` | สมัครรับ webhook ของเพจ |
| `pages_messaging` | ส่งข้อความและตอบกลับส่วนตัวทาง Messenger |
| `pages_manage_engagement` | ตอบหรือซ่อนคอมเมนต์ (ถ้าเปิดฟีเจอร์ตอบใต้คอมเมนต์) |

**ต้องเตรียม:**
- **ยืนยันธุรกิจ:** Business Verification ของบริษัทที่เป็นเจ้าของแอป
- **ขอสิทธิ์ระดับ Advanced Access:** ผ่าน App Review พร้อมวิดีโอสาธิตทุกสิทธิ์
- **เอกสารบนเว็บไซต์:** นโยบายความเป็นส่วนตัว และหน้าลบข้อมูลผู้ใช้

กระบวนการนี้มักใช้เวลาหลายสัปดาห์ **ควรเริ่มยื่นตั้งแต่สัปดาห์แรก**

### Token

- **ขั้นตอน:** ร้านล็อกอินผ่าน Facebook Login → ได้ User token → แลกเป็น Long-lived token → ดึง Page token ของแต่ละเพจ
- **เก็บรักษา:** เก็บ Page token แบบเข้ารหัส
- **เมื่อใช้ไม่ได้:** ถ้า token ใช้ไม่ได้ (ร้านเปลี่ยนรหัสผ่าน ถอนสิทธิ์ ฯลฯ) ระบบแจ้งเตือนในหน้าหลักและหน้าเชื่อมช่องทาง ให้ร้านเชื่อมใหม่

### ดึงคอมเมนต์

| ช่องทาง | ใช้เมื่อ | วิธี |
|---|---|---|
| สตรีมสด (SSE) | ระหว่างไลฟ์ | `GET https://streaming-graph.facebook.com/{live-video-id}/live_comments` แบบ Server-Sent Events ได้คอมเมนต์ใหม่ทันที |
| ดึงซ้ำเป็นรอบ | สำรองเมื่อสตรีมหลุด และใช้กับโพสต์ทั่วไป | `GET /{video-id หรือ post-id}/comments` เรียงใหม่ไปเก่า ดึงทุก 2–5 วินาทีระหว่างไลฟ์ |
| Webhook ของเพจ | คอมเมนต์ใต้โพสต์ที่ไม่ใช่ไลฟ์ และแจ้งเมื่อไลฟ์เริ่ม/จบ | สมัคร field `feed` และ `live_videos` |
| ดึงย้อนหลัง | ร้านเลือกไลฟ์ที่จบแล้วหรือโพสต์เก่า | `GET /{object-id}/comments` แบ่งหน้าจนครบ |

**ข้อควรระวัง:**
- **คอมเมนต์ซ้ำ:** คอมเมนต์อาจมาซ้ำจากหลายช่องทาง ใช้ `comment_id` กันซ้ำ (idempotent)
- **สตรีมหลุด:** ต่อใหม่อัตโนมัติ แล้วดึงช่วงที่ขาดด้วยการดึงซ้ำ
- **ตัวกรองของ Facebook:** การดึงคอมเมนต์ทั่วไปกรองคอมเมนต์คุณภาพต่ำออกโดยปริยาย ต้องตั้งให้ดึงทั้งหมด
- **เงื่อนไขของ API:** เป็นไปตามเอกสาร Meta ณ พ.ย. 2026 ต้องตรวจซ้ำก่อนพัฒนา

### ส่งลิงก์ชำระเงินทาง Messenger

- **วิธีส่ง:** `POST /{page-id}/messages` โดยใส่ `recipient: { comment_id }` (Private Reply)
- **ข้อจำกัด:**
  - ส่งได้ **1 ข้อความต่อ 1 คอมเมนต์** ภายใน **7 วัน**
  - หลังจากนั้นส่งต่อได้เมื่อลูกค้าตอบกลับ และอยู่ในกรอบ 24 ชั่วโมงของ Messenger
- **ผลต่อการออกแบบ:**
  - ส่งลิงก์ครั้งแรกเฉพาะคอมเมนต์ที่ **สร้างออเดอร์ใหม่**
  - คอมเมนต์ที่เพิ่มลงออเดอร์เดิมไม่ต้องส่งใหม่ ลิงก์เดิมแสดงยอดล่าสุดเสมอ
  - ปุ่มในข้อความ เช่น "ดูออเดอร์" ชวนให้ลูกค้าตอบ เพื่อเปิดกรอบ 24 ชั่วโมงสำหรับแจ้งสถานะต่อ
  - ถ้าส่งไม่ได้ (ลูกค้าปิดรับข้อความ หรือเกิน 7 วัน) แสดงสถานะในคอมเมนต์ แล้วให้แอดมินตอบใต้คอมเมนต์แทน

## ส่วนที่ 2 · เปลี่ยนคอมเมนต์เป็นออเดอร์

### กติกาจับรหัส (ร้านตั้งค่าได้)

- **รหัสสินค้า:** ทุก SKU มีรหัส CF เช่น `A01`
  - `A01` = 1 ชิ้น
  - `A01 2` หรือ `A01x2` = 2 ชิ้น
- **คำสั่งเพิ่ม:** เช่น "เพิ่ม", "อีก" ตามด้วยรหัส → เพิ่มลงออเดอร์เดิมของลูกค้าคนนั้นในรอบไลฟ์นั้น
- **คำที่ไม่นับ:** เช่น "ราคา", "เท่าไหร่" → ถือเป็นคำถาม ไม่สร้างออเดอร์
- **คำสั่งครบทุกแบบ:** รหัสสินค้าหลัก + คำที่ตั้งไว้ → สั่งทุก SKU ของสินค้านั้น
- **ลูกค้าคนเดียวในรอบไลฟ์เดียว:** รวมเป็นออเดอร์เดียวจนกว่าจะจ่าย
- **ลูกค้าในรายชื่อ "ไม่รับออเดอร์":** คอมเมนต์ไม่ถูกนับ

### สต็อก

- **จองสต็อกทันที** ตอนจับคอมเมนต์ (atomic) เพื่อไม่ให้ขายเกินระหว่างไลฟ์
- **ของไม่พอ:** ร้านเลือกได้ว่าจะปฏิเสธ หรือเก็บเป็นรายการรอของ
- **ออเดอร์ที่ไม่จ่าย:** ปิดเองตามเวลาที่ตั้ง (เช่น 24 ชม.) แล้วคืนสต็อก
- **เตือนก่อนปิด:** ส่งข้อความเตือนก่อนปิด ถ้ายังอยู่ในกรอบ 24 ชม.

## ส่วนที่ 3 · ระบบจัดการออเดอร์ (OMS)

### สถานะ

```
รอชำระ → รอจัดส่ง → รอพิมพ์ใบปะหน้า → รอขนส่งเข้ารับ → ส่งแล้ว
   └→ ยกเลิก (คืนสต็อก)
"มีปัญหา" เป็นป้ายแยก ติดได้ทุกสถานะ
```

- **เก็บปลายทาง:** ข้ามรอชำระ ไปรอจัดส่งเลย
- **ตรวจสลิป:**
  - ลูกค้าแนบสลิปในลิงก์ → "รอตรวจสลิป" → แอดมินยืนยัน
  - ถ้าจ่ายผ่าน QR ที่ตรวจยอดอัตโนมัติ → ยืนยันเอง
- **ประวัติ:** ทุกการเปลี่ยนแปลงบันทึกว่าใครทำอะไรเมื่อไร

### หน้าออเดอร์

ตามต้นแบบ `app/index.html`:
- แท็บสถานะ
- ตัวกรอง (รวมขั้นสูง) และตั้งค่าคอลัมน์
- แถวขยาย
- ทำทีละหลายรายการ
- แผงรายละเอียด
- อัปโหลดสลิป
- คืนเงิน

รายการข้อมูลที่ต้องมีครบอยู่ใน `design-skill/references/screens.md`

### หน้าลิงก์ชำระเงิน (ฝั่งลูกค้า)

- **เข้าถึง:** เปิดได้โดยไม่ต้องสมัครสมาชิก ใช้ลิงก์ที่มี token สุ่มต่อออเดอร์
- **ลูกค้าทำได้:**
  - ยืนยัน/แก้ที่อยู่ (วางทั้งก้อน ระบบแยกให้)
  - เลือกวิธีจ่าย: QR / โอน+สลิป / เก็บปลายทาง
  - ถ้าร้านเปิดไว้: แก้จำนวน เลือกขนส่ง ฝากของ
- **หลังจ่าย:** หน้าเดิมกลายเป็นหน้าติดตามสถานะและเลขพัสดุ

## ส่วนที่ 4 · จัดส่ง: เปิดกว้าง ไม่ผูกขาด

### สองวิธี ใช้พร้อมกันได้

| | บัญชีขนส่งของร้าน | ส่งผ่านรวมร้าน |
|---|---|---|
| สัญญา | ร้านมีสัญญากับขนส่งเอง | ไม่ต้องมี ใช้สัญญาพาร์ทเนอร์ของรวมร้าน |
| ราคา | ตามสัญญาของร้าน | ราคาพาร์ทเนอร์ที่รวมร้านตกลงไว้ |
| เชื่อมอย่างไร | แยกตามแบบของแต่ละขนส่ง: เข้าสู่ระบบเพื่ออนุญาต (Flash) · สมัครผ่านรวมร้าน (J&T) · Merchant ID (Kerry) · กระเป๋าเงิน (ไปรษณีย์ไทย) · User ID/Secret (SPX) · Client ID/Key (Ninja) · บัญชี DHL · เบอร์ + บัญชีรับ COD (Best) จากนั้นกรอกที่อยู่เข้ารับแล้วเปิดสวิตช์ | เปิดสวิตช์ใช้ได้ทันที |
| เก็บเงินค่าส่ง | ขนส่งเรียกเก็บจากร้านโดยตรง | หักจากเครดิตค่าส่งในระบบ |
| เงิน COD | โอนเข้าบัญชีร้านตามสัญญาขนส่ง | ขนส่งโอนให้รวมร้าน แล้วรวมร้านโอนต่อให้ร้าน (ต้องมีรอบโอนและรายงานกระทบยอด) |

### การเลือกขนส่ง

- **ทีละออเดอร์หรือหลายออเดอร์:**
  1. ระบบขอราคาจากทุกขนส่งที่ร้านเปิดไว้ ทั้งสองวิธี
  2. แสดงเทียบราคา เวลาถึง และเวลาเข้ารับ พร้อมป้าย "ถูกที่สุด" / "เร็วที่สุด"
  3. จองแล้วได้เลขพัสดุ ไปแท็บรอพิมพ์ใบปะหน้า
- **เลือกอัตโนมัติ** (ร้านตั้งค่าได้):
  - หลักการ: ถูกที่สุด / เร็วที่สุด / ขนส่งหลัก / ตามที่ลูกค้าเลือก
  - ใช้บัญชีของร้านก่อน
  - ออเดอร์ COD กรองเฉพาะขนส่งที่รองรับ
- **ใบปะหน้า:** ขอจากขนส่งเป็น PDF/ZPL แล้วรวมพิมพ์ทีละหลายใบ

### ชั้นเชื่อมขนส่ง (Carrier Adapter)

ทุกขนส่งใช้ interface เดียวกันในระบบ:

```ts
interface CarrierAdapter {
  quote(req: QuoteRequest): Promise<Quote[]>            // ขอราคา
  createShipment(req: ShipmentRequest): Promise<Shipment> // สร้างพัสดุ ได้เลขพัสดุ
  getLabel(shipmentId: string, format: 'pdf'|'zpl'): Promise<Buffer>
  schedulePickup(req: PickupRequest): Promise<Pickup>
  cancel(shipmentId: string): Promise<void>
  track(trackingNo: string): Promise<TrackingEvent[]>
}
```

- **บัญชีของร้าน:** adapter ใช้ credential ของร้าน (เก็บเข้ารหัส แยกต่อร้าน)
- **ผ่านรวมร้าน:** adapter ใช้ credential หลักของรวมร้าน แล้วบันทึกค่าส่งเป็นรายการหักเครดิต
- **ขนส่งรายใหม่:** เชื่อมเข้ามาเองได้ผ่าน **Carrier Partner API** (ดู `carrier-partner-api.md`) โดยไม่ต้องรอเราเขียน adapter ให้

## ส่วนที่ 5 · สถาปัตยกรรมและเทคโนโลยี

| ส่วน | เลือกใช้ | เหตุผล |
|---|---|---|
| หน้าบ้าน | Vue 3 + TypeScript + Element Plus | ตรงกับต้นแบบ ตารางและฟอร์มครบ |
| หลังบ้าน | NestJS (TypeScript) | ทีมเดียวกันเขียนได้ทั้งหน้าและหลัง แยกโมดูลชัด |
| ฐานข้อมูล | PostgreSQL | ออเดอร์และเงินต้องการ transaction |
| แคชและล็อก | Redis | จองสต็อกแบบ atomic เก็บสถานะสตรีมไลฟ์ |
| คิวงาน | BullMQ (บน Redis) | ประมวลผลคอมเมนต์ ส่งข้อความ ขอราคาขนส่ง ซิงก์สถานะ |
| Real-time ถึงหน้าจอ | WebSocket (Socket.IO) | คอมเมนต์และออเดอร์ใหม่ขึ้นทันที |
| ไฟล์ | Object storage (S3 หรือเทียบเท่า) | สลิป ใบปะหน้า รูปสินค้า |
| ที่ตั้ง | AWS ภูมิภาคสิงคโปร์ หรือผู้ให้บริการคลาวด์ในไทย | ใกล้ผู้ใช้ และพิจารณาเรื่อง PDPA |

**โมดูลหลังบ้าน:**

```
auth            ร้าน ผู้ใช้ บทบาท
channel-fb      เชื่อมเพจ token webhook ตัวรับสตรีมไลฟ์
live            รอบไลฟ์ กติกา CF ตัวแยกคอมเมนต์
catalog         สินค้า SKU รหัส CF สต็อก การจอง
orders          ออเดอร์ สถานะ ประวัติ ป้าย
payments        สลิป QR คืนเงิน เครดิตลูกค้า
messaging       ส่งข้อความ Messenger เทมเพลต ตอบอัตโนมัติ
shipping        adapter ขนส่ง ขอราคา จอง ใบปะหน้า ติดตาม เครดิตค่าส่ง COD
carrier-api     API สาธารณะสำหรับขนส่งพาร์ทเนอร์
reports         ยอดขาย รอบไลฟ์
```

**เส้นทางของคอมเมนต์:**

```
SSE / ดึงซ้ำ / webhook → คิว "comments" (กันซ้ำด้วย comment_id)
  → ตัวแยกรหัส → จองสต็อก (Redis + Postgres transaction)
  → สร้างหรือเพิ่มออเดอร์ → คิว "messenger" ส่งลิงก์
  → WebSocket แจ้งหน้าจอไลฟ์และหน้าออเดอร์
```

## ความเสี่ยงที่ต้องจัดการ

| ความเสี่ยง | วิธีรับมือ |
|---|---|
| Meta รีวิวไม่ผ่านหรือช้า | เริ่มยื่นสัปดาห์แรก ทำวิดีโอสาธิตครบ ระหว่างรอใช้บัญชีทดสอบของแอป |
| กติกา API ของ Meta เปลี่ยน | แยกโค้ด Facebook ไว้ในโมดูลเดียว ตรวจ changelog ทุกเดือน |
| สตรีมคอมเมนต์หลุดกลางไลฟ์ | ดึงซ้ำเป็นทางสำรองเสมอ และกันซ้ำด้วย comment_id |
| ขายเกินช่วงคอมเมนต์ถล่ม | จองสต็อกแบบ atomic ใน Redis แล้วบันทึกลง Postgres |
| ส่งข้อความไม่ได้ (เกิน 7 วัน / ลูกค้าปิดรับ) | แสดงสถานะให้แอดมินเห็น และตอบใต้คอมเมนต์แทน |
| เงิน COD ผ่านรวมร้าน | ต้องมีบัญชีพักเงิน รอบโอน และรายงานกระทบยอด ปรึกษาด้านกฎหมายและภาษีก่อนเปิด |
| ข้อมูลส่วนบุคคลลูกค้า (PDPA) | เก็บเท่าที่จำเป็น เข้ารหัส มีหน้าลบข้อมูล และกำหนดระยะเวลาเก็บ |
