# รวมร้าน: ระบบของเราคืออะไร และจะไปทางไหน

> เอกสารหลักของโปรเจกต์ ทุกครั้งที่ศึกษาเว็บตัวอย่างหรือเพิ่มฟีเจอร์ ให้กลับมาอัปเดตไฟล์นี้ก่อน
> "รวมร้าน" เป็นชื่อชั่วคราว
> อัปเดตล่าสุด: 16 พ.ย. 2026

---

## 1. รวมร้านคืออะไร

**รวมร้านคือระบบหลังร้านสำหรับคนขายของออนไลน์ในไทย ที่ขายผ่านไลฟ์และแชตเป็นหลัก**

ระบบดึงคอมเมนต์จากไลฟ์ Facebook มาเปลี่ยนเป็นออเดอร์ให้อัตโนมัติ เก็บเงิน และจัดการออเดอร์ทั้งหมดในที่เดียว
ร้านส่งของด้วยขนส่งเจ้าไหนก็ได้

**ประโยคเดียว:** "ไลฟ์จบ ออเดอร์ครบ เงินเข้า ของออก โดยไม่ต้องจดมือ"

### ปัญหาที่เราแก้

| ปัญหาของแม่ค้าไลฟ์วันนี้ | รวมร้านแก้อย่างไร |
|---|---|
| ต้องจดคอมเมนต์ CF ด้วยมือ ตกหล่น สั่งซ้ำ ขายเกินสต็อก | จับรหัสสินค้าจากคอมเมนต์อัตโนมัติ จองสต็อกทันที รวมคนเดิมเป็นออเดอร์เดียว |
| ทักแชตทีละคนเพื่อขอที่อยู่และสลิป | ส่งลิงก์ชำระเงินทาง Messenger ให้อัตโนมัติ ลูกค้ากรอกที่อยู่และแนบสลิปเอง |
| ตรวจสลิปเหนื่อย ไม่รู้ใครจ่ายแล้ว | ออเดอร์แยกตามสถานะชัดเจน ตรวจสลิปและยืนยันทีละหลายรายการ |
| ต้องเข้าเว็บขนส่งหลายเจ้า กรอกซ้ำ | เทียบราคาทุกขนส่งในหน้าเดียว จองและพิมพ์ใบปะหน้าทีละหลายใบ |
| ระบบอื่นบังคับใช้ขนส่งของเขา | **ใช้ขนส่งไหนก็ได้:** บัญชีของร้านเอง หรือขนส่งพาร์ทเนอร์ผ่านเรา |
| ไม่รู้ว่าไลฟ์รอบไหนกำไร | สถิติรอบไลฟ์: ยอด ยอดจ่ายจริง ยกเลิก ขายเกิน และกำไรประมาณการ |

### ใครใช้

- **แม่ค้าไลฟ์ / เจ้าของร้าน:** เปิดไลฟ์ ดูยอดสด ดูกำไร
- **แอดมิน:** ตรวจสลิป แก้ออเดอร์ ตอบแชต
- **ฝ่ายแพ็ก:** เลือกขนส่ง สแกนตรวจสินค้า พิมพ์ใบปะหน้า
- **ลูกค้าปลายทาง:** กดลิงก์ จ่ายเงิน ติดตามพัสดุ (ไม่ต้องสมัครอะไร)
- **บริษัทขนส่ง:** เชื่อม API เข้ามาเป็นพาร์ทเนอร์ (ดู `carrier-partner-api.md`)

### หลักการออกแบบของเรา

1. **ง่ายก่อน ละเอียดเมื่อต้องการ:** หน้าจอแสดงงานถัดไปที่ต้องทำ ส่วนคำสั่งละเอียดซ่อนในเมนู ไม่ตัดทิ้ง
2. **คิดแบบคนไทย:**
   - คำไทยที่คนขายใช้จริง และเข้าใจคอมเมนต์แบบ "CF A01 2 ตัว"
   - รองรับพร้อมเพย์และสลิป วางที่อยู่ทั้งก้อนแล้วระบบแยกให้
   - ใช้งานบนมือถือได้
3. **เปิดกว้าง ไม่ผูกขาด:** ขนส่ง ช่องทางชำระเงิน และโปรแกรมบัญชี ร้านเลือกเองได้
4. **อัตลักษณ์ของเราเอง:** เรียนหลักการจากคู่แข่งได้ แต่ไม่ลอกหน้าตา เลย์เอาต์ หรือข้อความ (ดู `design-skill/references/design-system.md` ส่วนที่ 3)

## 2. สิ่งที่เราเรียนรู้จากเว็บตัวอย่าง

เว็บตัวอย่างเป็นระบบประเภท "ขายผ่านไลฟ์ + จัดการออเดอร์หลายช่องทาง" ที่ทำมาจากต่างประเทศ
เราศึกษาเพื่อรู้ว่าตลาดคาดหวังอะไรจากระบบประเภทนี้ ไม่ได้นำงานออกแบบมาใช้

| หัวข้อ | เว็บตัวอย่างทำอย่างไร (หลักการ) | รวมร้านทำอย่างไร |
|---|---|---|
| เทคโนโลยี | Vue 3 + Element Plus | ใช้เทคโนโลยีเดียวกัน (มาตรฐานเปิด) แต่ธีม สี ฟอนต์ และส่วนประกอบเป็นของเรา |
| โครงหน้ารายการ | แท็บสถานะ → ตัวกรอง → ตาราง → ปุ่มทำต่อ | ใช้หลักเดียวกัน แต่ตัวกรองเป็นชิปกด และมีปุ่มหลักที่บอกงานถัดไป |
| ความละเอียด | ตัวกรอง คำสั่งหลายรายการ ป้าย และส่งออกครบมาก | เก็บความละเอียดครบ (ดูเช็กลิสต์ใน `design-skill/references/screens.md`) แต่จัดเป็นชั้นให้ไม่รก |
| ขนส่ง | รายชื่อขนส่งที่ระบบเชื่อมไว้ให้แล้ว แต่ละเจ้ามีปุ่ม "อนุญาตบัญชี" ที่ต่างกันตามขนส่ง (ดูส่วนที่ 2.1) แล้วเปิดสวิตช์ใช้งานพร้อมกรอกที่อยู่ผู้ส่ง · ใช้บัญชีของร้านเองเท่านั้น | ทำแบบเดียวกัน (เชื่อมแยกตามแบบของแต่ละขนส่ง + ที่อยู่เข้ารับแยกต่อขนส่ง + ขนส่งที่กรอกเลขพัสดุเอง) **และเพิ่ม** "ส่งผ่านรวมร้าน" ด้วยราคาพาร์ทเนอร์ กับ API ให้ขนส่งรายใหม่เชื่อมเข้ามาเอง |
| กลุ่มผู้ใช้ | ออกแบบแบบ ERP สำหรับผู้ใช้ทั่วไป | **ต่างจากเขา:** ออกแบบให้แม่ค้าไลฟ์ไทยที่ไม่เคยใช้ ERP ใช้ได้ทันที |
| ภาษา | แปลมาจากภาษาอื่น บางคำไม่เป็นธรรมชาติ | เขียนภาษาไทยเองทั้งหมด |

### 2.1 ผลสำรวจหน้าเชื่อมขนส่งของเว็บตัวอย่าง (17 พ.ย. 2026)

**ขั้นตอนของเขา:**
1. หน้ารายการขนส่ง: โลโก้ · ชื่อ · สวิตช์เปิดใช้ · ปุ่มอนุญาตบัญชี
2. กดอนุญาตบัญชี → แผงด้านข้างที่ช่องกรอก **ไม่เหมือนกันในแต่ละขนส่ง**
3. เปิดสวิตช์ → แผงกรอกข้อมูลผู้ส่ง (ที่อยู่ ผู้ติดต่อแบบตั้งเองหรือใช้ชื่อเพจ เบอร์ รหัสไปรษณีย์)
4. มีแท็บกฎค่าส่งแยกต่างหาก และมีขนส่งที่ร้านเพิ่มเอง

**ไม่มี:** ช่องกรอก API key แบบเดียวใช้ทุกเจ้า และไม่มีการส่งผ่านบัญชีของแพลตฟอร์ม

| ขนส่ง | วิธีเชื่อมในเว็บตัวอย่าง | ของเรามีหรือยัง |
|---|---|---|
| Flash | เข้าสู่ระบบ Flash เพื่ออนุญาต แล้วกลับมายืนยัน | ✅ มีแล้ว |
| J&T | สมัครผ่านระบบด้วยข้อมูลผู้ส่ง (ลูกค้าทั่วไป) หรือใช้บัญชี VIP | ✅ มีแล้ว |
| Kerry | Merchant ID ที่ได้ตอนเปิดบัญชีที่สาขา | ✅ มีแล้ว |
| ไปรษณีย์ไทย | เบอร์โทรที่ผูกกระเป๋าเงิน + ตรวจสิทธิ์ COD | ✅ มีแล้ว |
| SPX | User ID + User Secret ขอจากฝ่ายบริการลูกค้า + เข้ารับ / ส่งที่สาขา | ✅ มีแล้ว |
| Best | เบอร์ผูกบัญชี + เข้ารับ / ส่งที่สาขา + บัญชีธนาคารรับเงิน COD | ✅ มีแล้ว |
| Ninja Van | Client ID + Key + เข้ารับ / ส่งที่สาขา + ช่วงเวลาเข้ารับ + ตรวจสอบสิทธิ์ | ✅ มีแล้ว |
| DHL | Client ID · รหัสผ่าน · บัญชีเข้ารับ · บัญชีผู้ซื้อบริการ · ประเภทบริการ · ประกัน + ตรวจสอบสิทธิ์ | ✅ มีแล้ว |
| ขนส่งที่ร้านเพิ่มเอง | ไม่ต้องอนุญาต | ✅ มีแล้ว ("ขนส่งอื่นที่ไม่ได้เชื่อมระบบ" กรอกเลขพัสดุเอง) |
| ส่งผ่านแพลตฟอร์ม | ไม่มี | ➕ ของเราเพิ่ม: "ส่งผ่านรวมร้าน" (ระยะ 2) |

## 3. ตอนนี้ทำถึงไหนแล้ว

**ช่วงปัจจุบัน:** ต้นแบบหน้าจอที่กดลองได้ (ระยะ 0)
- เปิดดูได้ที่ `app/index.html` และรูปทุกหน้าอยู่ใน `screens/`
- ทุกหน้าใช้ข้อมูลตัวอย่างในเบราว์เซอร์ ยังไม่มีระบบหลังบ้าน

## 4. แผนในอนาคต

ระยะเวลาเป็นค่าประมาณสำหรับทีม 2–3 คน เรียงตามลำดับความสำคัญ และปรับได้ตามผลทดสอบกับร้านจริง

### ระยะ 0 · ต้นแบบหน้าจอ ✅ (เสร็จแล้ว)
ออกแบบทุกหน้า ทดสอบลำดับการทำงาน และเขียนสกิลออกแบบกับเอกสารสเปก

### ระยะ 1 · MVP ไลฟ์ Facebook ใช้จริง (ประมาณ 8 สัปดาห์)
เป้าหมาย: ร้านจริง 3–5 ร้านใช้ขายไลฟ์ได้ตั้งแต่ต้นจนจบ
- ยื่น Meta Business Verification และ App Review (เริ่มสัปดาห์แรก)
- สร้างระบบหลังบ้านจริง: NestJS + PostgreSQL + Redis + คิวงาน
- ดึงคอมเมนต์สดและย้อนหลัง → ออเดอร์ → จองสต็อก
- ส่งลิงก์ชำระเงินทาง Messenger
- ลิงก์ชำระเงิน: โอน / พร้อมเพย์ + แนบสลิป
- OMS ครบสถานะ
- เชื่อมขนส่งด้วยบัญชีร้าน 2 เจ้าแรก: ขอราคา จอง ใบปะหน้า ติดตาม
- รายงานพื้นฐานและสถิติรอบไลฟ์

รายละเอียดอยู่ใน `facebook-live-oms-mvp.md`

### ระยะ 2 · เครือข่ายขนส่งและเงิน (ประมาณ 6–8 สัปดาห์)
- Carrier Partner API ใช้จริง และรับขนส่งพาร์ทเนอร์เข้าระบบ
- ส่งผ่านรวมร้าน: เครดิตค่าส่ง ใบแจ้งหนี้
- COD: รอบโอนเงิน กระทบยอด (ต้องปรึกษากฎหมายและภาษีก่อน)
- ตรวจสลิปอัตโนมัติ (อ่านสลิปและเทียบยอด)
- ช่องทางรับเงินออนไลน์: QR ไดนามิก บัตร
- LINE OA: แชตและส่งลิงก์ชำระเงิน
- Instagram ไลฟ์และคอมเมนต์

### ระยะ 3 · รวมทุกช่องทางขาย (ประมาณ 8–10 สัปดาห์)
- เชื่อม Shopee, TikTok Shop, Lazada: ดึงออเดอร์ อัปโหลดสถานะจัดส่ง
- สต็อกเดียวซิงก์ทุกช่องทาง
- จับคู่สินค้าข้ามช่องทาง จับคู่คลังแพลตฟอร์ม และกลุ่มร้าน
- พิมพ์ใบปะหน้าของแพลตฟอร์ม และรวมงานแพ็กจากทุกช่องทาง

### ระยะ 4 · หลังบ้านเต็มรูปแบบ
- **คลังสินค้า:** รับเข้า เบิกออก โอนคลัง นับสต็อก หลายคลัง
- **ซื้อของ:** สั่งซื้อจากซัพพลายเออร์และดรอปชิป พร้อมสถานะการจ่าย
- **บัญชี:**
  - ส่งข้อมูลไปโปรแกรมบัญชีไทย (เช่น PEAK, FlowAccount)
  - ใบกำกับภาษี / e-Tax Invoice
- **ทีม:** สิทธิ์ละเอียดระดับปุ่ม และประวัติการใช้งานทุกส่วน

### ระยะ 5 · ผู้ช่วยอัจฉริยะและแอปมือถือ
- **ผู้ช่วยอัจฉริยะ (AI):**
  - เข้าใจคอมเมนต์ภาษาไทยแบบพิมพ์ผิดหรือภาษาพูด
  - ช่วยตอบแชต
  - สรุปไลฟ์และแนะนำสินค้าที่ควรขายรอบหน้า
- **แอปมือถือ:**
  - แม่ค้าดูยอดสดระหว่างไลฟ์
  - ฝ่ายแพ็กสแกนสินค้าและพิมพ์ใบปะหน้าผ่านเครื่องพิมพ์พกพา

## 5. รูปแบบธุรกิจ (ร่าง ต้องตัดสินใจ)

| รายได้ | แนวคิด |
|---|---|
| ค่าสมาชิกรายเดือน | แบ่งแพ็กเกจตามจำนวนออเดอร์ / เพจ / ผู้ใช้ มีแพ็กเกจเริ่มต้นราคาย่อมเยา |
| ส่วนต่างค่าขนส่ง | เฉพาะเมื่อร้านเลือก "ส่งผ่านรวมร้าน" ถ้าร้านใช้บัญชีตัวเอง เราไม่คิดเพิ่ม |
| ค่าบริการเสริม | ตรวจสลิปอัตโนมัติ, ผู้ช่วย AI, ใบกำกับภาษีอิเล็กทรอนิกส์ |

### เรื่องที่ต้องตัดสินใจ
1. ชื่อแบรนด์จริงแทน "รวมร้าน" และจดเครื่องหมายการค้า
2. ขนส่ง 2 เจ้าแรกที่จะเชื่อมในระยะ 1
3. ส่วนต่างค่าส่งในโหมดผ่านรวมร้าน
4. วิธีถือและโอนเงิน COD
5. ราคาแพ็กเกจ
6. ร้านนำร่อง 3–5 ร้าน

## 6. กติกาเมื่อศึกษาเว็บตัวอย่างครั้งต่อไป

ทุกครั้งที่ไปดูเว็บตัวอย่าง ต้องบันทึกผลเป็น 3 ช่องเสมอ:

| สิ่งที่พบในเว็บตัวอย่าง | ระบบของเรามีหรือยัง | เราจะทำเมื่อไร / ทำต่างอย่างไร |
|---|---|---|
| (หลักการหรือฟังก์ชัน เขียนด้วยคำของเรา) | มีแล้ว / ยังไม่มี / ไม่ทำ | ระยะที่ … · เหตุผล |

- **ห้ามคัดลอก:** ข้อความ รูป โลโก้ หรือสีของเว็บตัวอย่างลงเอกสาร
- **ห้ามเปิดเผย:** บัญชีทดลองหรือข้อมูลในบัญชีนั้น
- **ห้ามเปลี่ยนข้อมูล:** ไม่กดปุ่มที่บันทึก ลบ ส่ง หรือจ่ายเงินในเว็บตัวอย่าง
- **อัปเดตที่เดียว:** แก้ไฟล์นี้ (ส่วนที่ 3 และ 4) และเช็กลิสต์ใน `design-skill/references/screens.md`
